# 管理画面の4つのシステム

各タブは専用画面と処理モジュールを持つ。同じGASプロジェクト・認証・デプロイを共用する。インフラまで独立した4サービスではない。

| 入口のsystem値 | 内容 |
| --- | --- |
| setup | ① 募集要項、空欄様式、記入済み見本、必要項目案 |
| applications | ② 会社台帳、保存済み申請データ、提出・案内履歴、保存先 |
| transfer | ③ 転記用データの確認、確定保存、再読込 |
| forms | ④ 実際の申請者フォームのプレビュー、会社向けリンク発行、明示操作によるメール送信 |

## 申請者フォーム

④で会社台帳と、任意の保存済み申請を選ぶ。台帳は許可した基本項目のみ使用し、管理者用番号は申請者画面へ渡さない。過去の申請を使う場合は同じ会社であることをサーバーでも検証する。申請データは台帳より優先し、基本情報・従業員・男女別人数・分岐回答を事前入力する。過去の添付ファイルは引き継がない。

実際の申請者URLとプレビューはWomenR8.htmlを共用する。プレビューは管理者限定で、④内のsandbox付きiframeと別タブで確認できる。プレビューでは送信できず、サーバーもpreviewMode=trueの送信を拒否する。プレビュー操作は案内履歴を作らず、メールも送らない。

会社向けリンク発行時に事前入力を固定する。以後の台帳・申請変更で発行済みリンクの事前入力は変わらない。大きい従業員データは非公開Driveファイルに保存し、Script Propertiesの単一値上限を回避する。宛先メールは発行時に入力したものを使う。従来の案内リンク・保存先・会社ID・受付データを維持する。

## 転記と現在の範囲

③は受付IDを使い②の申請データを読み、①の様式参照先とともに確定JSONを別領域へ保存する。確定保存した入力値は後の台帳・様式変更で上書きしない。

現在の申請者フォームは令和8年度女性活躍情報公開促進奨励金が対象。①の募集要項下書きから新しい助成金の入力画面を自動生成するAI処理、Word・Excel・PDFへの自動転記は未実装。

GitHub Actionsで `node --test tests/system-boundaries.test.cjs`、clasp同期、同期後のソース照合、既存Webアプリ更新を実行する。
