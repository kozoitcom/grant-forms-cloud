# 管理画面の3つのシステム

管理画面は次の独立した画面と処理モジュールを持つ。同じGASプロジェクト、認証、デプロイを共用するため、インフラや障害範囲まで独立した3サービスではない。

| 入口 | 画面 | 処理 | 保存内容 |
| --- | --- | --- | --- |
| `?page=admin&system=setup` | GrantSetupView.html | GrantSetup.js | 募集要項、入力項目案、空欄様式、記入済み見本 |
| `?page=admin&system=applications` | ApplicantDataView.html | ApplicantData.js | 会社台帳、案内履歴、入力データ、提出書類、保存先設定 |
| `?page=admin&system=transfer` | DocumentTransferView.html | DocumentTransfer.js | 転記用確定データ、保存履歴 |

コード.jsはルーティング、管理者認証、既存入口、共通の助成金・提出書類カタログを保持する。GrantAdmin.htmlは共通のナビゲーションと、選ばれた画面だけを読み込む。各画面のJavaScriptとDOMは他画面を読み込まず動作する。

## データの受け渡し

システム3は、システム2の提出済み申請を受付IDで選択し、システム1の様式参照情報を取得する。`getTransferPreparation`の返却形式はschemaVersion 1。確定保存時に入力値・従業員・人数・様式のファイルIDをJSONへ保存する。受付ID、会社、助成金、保存日時を含む。保存済みJSONから再開でき、以後の台帳や様式変更では上書きしない。

保存先のScript Propertiesキー、会社ID、案内トークン、受付スプレッドシート、過去の提出書類は変更・移行しない。既存の申請者URLも維持する。新しい保存領域は転記用確定データの専用フォルダだけである。

## 現在の範囲

- 募集要項のAI解析・新しい動的フォームの生成は未実装。入力項目案の下書き保存と、既存助成金の様式設定が利用可能。
- Word・Excel・PDFへの自動転記は未実装。システム3では転記元・様式登録状況の確認、確定データの保存・再読込まで利用可能。
- 会社台帳を変更しても、過去に提出された申請や確定した転記データを自動上書きしない。
- タブ切替は画面遷移。入力中の内容は各画面で保存してから切り替える。
- 管理画面と新しいAPIは既存の管理者認証を必須とする。共有設定は変更しない。

`node --test tests/system-boundaries.test.cjs`で、ルーティング、画面分離、データ受け渡し、確定保存の独立性、権限拒否、未初期化時の読取を検証する。GitHub Actionsでテスト、clasp同期、同期後照合、既存Webアプリ更新を順に実行する。
