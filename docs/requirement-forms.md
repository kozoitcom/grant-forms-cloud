# 必要項目の作成・編集・公開（2.4.0）

①の一括登録後、「必要項目の作成・編集・公開」で資料を選択する。助成金名・年度を設定し、各資料を順番に解析する。項目名・入力形式・必須・使用する・説明・選択肢・資料根拠・転記先・表示条件を編集する。AI候補の一致はIDまたはNFKC正規化項目名で検出し、候補から統合／別項目／不採用を明示する。意味の違いは管理者が確認する。公開済みの項目IDは削除せず無効化する。

## GPT接続（本人による初回設定）
①の「GPT接続設定」でOpenAI APIキーとGPTモデルIDを保存する。初期モデルは `gpt-6.1-terra`。キーは `OPENAI_API_KEY`、モデルは `GRANT_OPENAI_MODEL` として管理者専用GASスクリプトプロパティに保存。既存キーは取得・表示せず、空欄保存なら保持する。入力欄は保存要求時に消去する。OpenAIキーはGeminiキーと別物。Geminiへのフォールバックは行わない。既存のGemini設定値は保持するが使用しない。

ChatGPTの会話や月額利用枠へ埋め込む方式ではなく、管理画面からOpenAI Responses APIへ接続する。API利用料・残高・利用権限は利用するOpenAIプロジェクトに従う。自動で請求先登録や残高追加をしない。資料送信とAPI利用を確認するチェック後のみ実資料を送る。接続テストはモデルメタデータのGETだけで資料を送らない。モデル存在のテストは解析の成功や残高を保証しない。

PDF・DOCX・XLSXを15 MB以内で `input_file` のdata URIとして直接送信する。Driveのファイルを公開しない。`store:false`、出力最大20,000トークン、strict JSON schema、完了・拒否・不完全応答・業務ルールを確認。入力ファイルの読取処理に制約があり、非PDFの画像・図形やExcelの複雑なプルダウン条件は完全抽出を保証しない。確認用PDFを併用し、GPTのwarningsと原本を照合する。

外部通信権限が未承認ならGoogleの本人承認リンクを表示する。5xxだけ最大3回、2秒・4秒を基準にジッター付きで再試行し、429・401・403等は停止して理由を表示する。キー・プロバイダーの生レスポンス・送信資料はログへ出さない。処理成功済みの資料は同じ画面内での再実行時にスキップする。画面を閉じる前に下書きを保存する。

## 公開と会社リンク
下書きプレビューは管理者のみ。送信不可。下書き保存と公開を分離し、公開時点の定義を保存する。
- 今後だけ：新規リンクは新しい公開版。既存の会社リンクは従前の版を維持。
- 未提出会社にも：以前発行済みの未提出リンクにも更新版を適用。入力中に更新されると送信は拒否され、再読み込みを案内。
- 特定会社だけ：当該項目定義に属する未提出・有効な案内のみ指定でき、他社・一般公開版は変更しない。
④の助成金選択肢に公開済みの項目定義が追加される。既存women-r8の固定フォーム・リンクはそのまま保持し、新方式のフォームは別の選択肢になる。初回は新方式のリンクを発行する。旧固定フォームへの自動置換は行わない。

回答・添付PDF・当時の項目定義を指定Drive保存先へ保存。添付は合計20 MB。受付後は二重提出せず同じ受付IDを返す。②の申請一覧・③の転記準備へ接続。③の実際のWord/Excel/PDFへの自動転記は従来どおり未実装。提出後の追加回答リンク・保存済み書類の再生成・自動通知は今回対象外。提出済みレコードは変更しない。

表示条件は一段（他の条件付き項目への依存や循環は不可）。従業員の人数分追加などの繰り返しグループは新方式では未対応。旧固定フォームの従業員機能は維持。
